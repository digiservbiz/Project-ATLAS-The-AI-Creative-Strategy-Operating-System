# ATLAS AI — Memory System Specification

**Version:** 1.0.0  
**Status:** Foundation  
**Branch:** `dev`

## 1. Purpose

ATLAS memory makes the system persistent across conversations and workflow runs. Memory is not a transcript archive. It is a controlled system for retaining durable facts, decisions, preferences, learnings, experiment results, and proven patterns.

## 2. Knowledge vs Memory

**Knowledge** is reusable information about a subject or domain.

**Memory** is information learned or decided in a specific ATLAS organization, project, brand, or campaign.

Examples:

- Knowledge: principles of direct-response copywriting.
- Memory: this brand's audience responds better to proof-first hooks.

## 3. Memory Types

### Fact
A verified project fact.

### Decision
A deliberate human or system decision that should influence future work.

### Preference
A user or brand preference.

### Learning
A conclusion derived from research, execution, or analysis.

### Experiment Result
A measured outcome from a test.

### Winning Pattern
A reusable pattern supported by campaign evidence.

### Failure Pattern
A pattern associated with poor performance or rejected work.

## 4. Memory Lifecycle

```text
Observe
  ↓
Extract candidate memory
  ↓
Normalize
  ↓
Validate
  ↓
Score importance/confidence
  ↓
Persist
  ↓
Retrieve when relevant
  ↓
Update or supersede
```

Memory should not be created from every sentence generated by an agent.

## 5. Memory Record

Conceptual structure:

```json
{
  "memory_id": "uuid",
  "organization_id": "uuid",
  "project_id": "uuid",
  "campaign_id": "uuid",
  "type": "winning_pattern",
  "statement": "Proof-first openings outperform polished introductions for this audience.",
  "evidence": ["artifact-id", "experiment-id"],
  "confidence": 0.86,
  "importance": 0.92,
  "scope": "brand",
  "status": "active",
  "created_at": "ISO-8601",
  "updated_at": "ISO-8601"
}
```

## 6. Scope

Memory has an explicit scope:

- `organization`
- `project`
- `brand`
- `campaign`
- `user`

More specific memory overrides broader memory when there is a conflict.

## 7. Memory Confidence

Confidence describes confidence in the memory claim, not model confidence in writing it.

Possible basis:

- User explicitly stated it.
- Multiple independent sources support it.
- Controlled experiment supports it.
- Single observation.
- Agent inference.

Experimental evidence should generally receive higher confidence than an unsupported inference.

## 8. Importance

Importance determines how strongly a memory should be retained and surfaced.

High-importance examples:

- Approved positioning.
- Legal/brand restrictions.
- Explicit user preferences.
- Proven winning creative pattern.
- Important campaign failure.

Low-importance examples:

- Temporary wording preference.
- One-off draft decision.

## 9. Memory Creation Rules

Create memory when information is:

1. Durable.
2. Relevant to future decisions.
3. Supported by evidence or explicit user instruction.
4. Specific enough to retrieve accurately.

Do not create memory for:

- Generic filler.
- Temporary reasoning.
- Unverified speculation.
- Sensitive information that ATLAS is not authorized to retain.
- Duplicate memories with no new information.

## 10. Memory Extraction

The Memory Agent may inspect workflow artifacts and identify candidate memories.

It must return:

- Candidate statement.
- Type.
- Scope.
- Evidence.
- Importance.
- Confidence.
- Whether human confirmation is recommended.

## 11. Conflict Resolution

When new memory conflicts with existing memory:

1. Compare scope.
2. Compare evidence quality.
3. Compare recency.
4. Determine whether the new result supersedes the old result.
5. Preserve historical records.
6. Mark the old memory `superseded` rather than deleting it.

## 12. Retrieval

Memory retrieval should be hybrid:

- Metadata filters.
- Keyword search.
- Semantic/vector similarity.
- Recency.
- Importance.
- Scope.

The retrieval system should return a small relevant set rather than dumping all project memory into an agent prompt.

## 13. Retrieval Ranking

Conceptual ranking:

```text
relevance
+ scope match
+ evidence quality
+ importance
+ recency
- contradiction risk
```

The exact scoring formula should be evaluated empirically.

## 14. Memory Injection

The orchestrator decides which memories are supplied to an agent.

Each injected memory should include its source and scope.

Example:

```text
MEMORY
Scope: brand
Confidence: 0.86
Evidence: experiment-142
Statement: Proof-first hooks have historically produced stronger CTR for this audience.
```

## 15. User-Controlled Memory

Users should eventually be able to:

- View important memories.
- Correct memories.
- Delete memories.
- Mark memories as always relevant.
- Reject an automatically proposed memory.

A memory deletion should not erase immutable audit history where retention is legally or operationally required.

## 16. Privacy Boundary

ATLAS must not treat all conversation content as permanent memory.

Memory extraction must respect:

- User permissions.
- Organization boundaries.
- Data retention policy.
- Sensitive-data restrictions.
- Integration permissions.

## 17. Campaign Learning Loop

The primary learning loop is:

```text
Creative hypothesis
      ↓
Creative produced
      ↓
Campaign test
      ↓
Performance data
      ↓
Performance Agent
      ↓
Learning candidate
      ↓
Memory validation
      ↓
Winning/Failure Pattern
      ↓
Future Creative Strategy
```

This is one of ATLAS's core differentiators.

## 18. Memory Decay

Some memories become less relevant over time.

A future implementation may use:

- Time decay.
- Campaign recency.
- Repeated confirmation.
- Explicit supersession.

Critical brand decisions should not decay automatically.

## 19. Memory Safety

Memory must never be used as an unquestionable source of truth.

Agents should distinguish:

- Explicit fact.
- Historical decision.
- Experimental result.
- Inference.

A memory may be wrong, outdated, or scoped incorrectly.

## 20. MVP Memory

The first implementation requires only:

- `memories` table.
- Memory creation endpoint/service.
- Memory retrieval service.
- Scope filtering.
- Importance/confidence metadata.
- Supersession support.
- Memory Agent.

Vector memory can be introduced after the basic lifecycle works.

## 21. Acceptance Criteria

Memory is ready when:

- A workflow can create a memory.
- A later workflow can retrieve that memory.
- Organization/project/brand boundaries are enforced.
- Conflicting memories can be superseded without destroying history.
- Retrieval returns evidence and scope.
- Agents do not receive irrelevant memory by default.
